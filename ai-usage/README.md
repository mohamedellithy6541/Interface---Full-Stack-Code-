# AI usage

## Summary

I built this project with **Claude Code** (Claude Opus 5.5) as a pair programmer. I chose the stack and the
architecture and gave the instructions; the AI wrote most of the code, one layer at a time, and ran the tests
and checks. After each part I reviewed the result and asked questions until I understood it, and I changed
direction where I disagreed (for example: Docker instead of a CI/CD pipeline).

| Tool | Model | Used for |
| --- | --- | --- |
| Claude Code (Claude desktop app, Code tab) | Claude Opus 5.5 | Converting the assessment PDF to Markdown, scaffolding both projects, writing the backend layers and the Angular front end, unit tests, README, Dockerfiles and docker-compose |

**Evidence:** the full chat is in [`sessions/01-claude-code-session.md`](sessions/01-claude-code-session.md)
(the app's transcript export converted to Markdown; the top of the file says what was left out).
The main instructions are summarised in [`prompts/01-backend.md`](prompts/01-backend.md) and
[`prompts/02-frontend.md`](prompts/02-frontend.md).

## What I decided, and what the AI did

| I decided | The AI did |
| --- | --- |
| Stack: ASP.NET Core Web API on .NET 9, SQL Server, Angular 21 | Scaffolded the solution and the Angular app |
| Clean Architecture, CQRS (MediatR), AutoMapper, FluentValidation | Wrote the Domain, Application, Infrastructure and Api layers following those patterns |
| One global middleware for errors, RFC 7807 Problem Details | Wrote the middleware and mapped each exception type to a status code |
| One static registration class per layer for dependency injection | Wrote `AddApplication()`, `AddInfrastructure()`, `AddPresentation()` |
| JWT with HR / Employee roles, plus Google sign-in | Wrote the token service, Google token check, guards and server-side permission checks |
| An Angular client generated from Swagger ("ng swagger lib") | Set up ng-openapi-gen and built the pages on the generated services |
| Docker instead of CI/CD | Removed the CI workflow, wrote the Dockerfiles and docker-compose |
| Git history: one commit per meaningful step | Committed and pushed step by step |

## Judgment: where the first attempt was wrong or risky

Using AI well means checking its output, not accepting it. These are the points where something was caught and changed:

| Problem | How it was found | What was done |
| --- | --- | --- |
| AutoMapper 14 has known high-severity security advisories | NuGet warning during build | Upgraded to 16.3; 17.x was rejected because it needs .NET 10 |
| MediatR 13+ and AutoMapper 15+ need a commercial licence | Checked before choosing versions | MediatR pinned to 12.5 (free); AutoMapper takes an optional licence key |
| Validation errors (400) came back without the `errors` field | Manual API test with curl | Fixed in the global middleware |
| Request logs showed 500 for validation errors | Reading the Docker logs | Moved request logging outside the error middleware |
| Hire dates showed one day early in the UI | Clicking through the app in the browser | Removed a wrong time-zone argument |
| My own edit on GitHub made the push fail | `git push` was rejected | Took my edit first, then added the new commits on top (no force-push) |
| .NET 9 is not an LTS version, and the brief recommends LTS | Raised by the AI during my review | Kept .NET 9 as I asked; noted in the README |
| Secrets in the repository | Checked before every push | JWT key and database password only in `.env` / user-secrets; `.env.example` committed instead |

## How the work was verified

- **Automated tests:** 78 backend unit tests (xUnit) and 33 front-end unit and component tests (Vitest), all passing.
- **API checks:** every endpoint called with real requests: success cases, 400/401/403/404/409/422 errors, role rules.
- **Browser checks:** login, search, filters, paging, create, edit, delete, server errors shown on the right field,
  payslip, the Employee role's limits and expired sessions, both with `ng serve` and in Docker.
- **Docker:** `docker compose up` tested end to end (database, API, front end).

## My review questions

After the backend was built I asked the AI to explain it before going on: how the global exception handling works,
which exception types the Application layer uses, what kind of tests these are and why they count as unit tests,
which database is used, and an explanation of the payroll module in Arabic. These questions and answers are in the
session file.
