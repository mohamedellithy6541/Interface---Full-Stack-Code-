# AI usage

I used **Claude Code** (Anthropic, model Claude Opus 5.5) as a tool to improve my work:

- **to move faster:** I designed the application and directed the work; Claude Code wrote code from my
  instructions, one layer at a time, and ran the builds;
- **to raise the quality:** it caught problems such as a vulnerable library version and a missing field in error
  responses, and I reviewed each part and changed direction where I disagreed;
- **to test all the cases:** 111 automated unit tests (78 backend, 33 front end), plus hand testing of every API
  endpoint (success, 400, 401, 403, 404, 409 and 422 responses) and every screen in the browser, both locally and in Docker.

---

## The application

**Interface Employee & Payroll** lets an HR team manage employees and produce monthly payslips.

| Feature | What it does |
| --- | --- |
| Sign in | Email + password, or "Sign in with Google". Both return the app's own JWT |
| Roles | **HR** manages everything; an **Employee** can only see their own payslip (enforced by the API) |
| Employees | List with search (name/email), department and status filters, and paging; create, edit, delete with validation in the UI and on the server |
| Payslip | Pick a month and see base salary, allowances, gross pay, progressive income tax, capped social insurance, other deductions and net pay |
| Errors | Every error is an RFC 7807 Problem Details response; the UI shows each validation message under its field |
| Running it | `docker compose up` starts SQL Server, the API and the front end, with demo data |

**Stack:** ASP.NET Core Web API (.NET 9) with Clean Architecture, CQRS (MediatR), AutoMapper and FluentValidation;
EF Core + SQL Server; Angular 21 with SCSS and an API client generated from Swagger; Docker.

---

## My decisions

- The stack: ASP.NET Core Web API on .NET 9, SQL Server, Angular 21.
- Clean Architecture with CQRS (MediatR), AutoMapper and FluentValidation.
- One global middleware for errors, returning RFC 7807 Problem Details.
- One static registration class per layer for dependency injection.
- JWT with HR / Employee roles, plus Google sign-in.
- An Angular API client generated from Swagger (ng-openapi-gen).
- Docker instead of a CI/CD pipeline.
- A commit for each meaningful step.

## What was checked and changed

| Problem | How it was found | What was done |
| --- | --- | --- |
| AutoMapper 14 has known high-severity security advisories | NuGet warning | Upgraded to 16.3 (17.x needs .NET 10) |
| MediatR 13+ and AutoMapper 15+ need a commercial licence | Checked before choosing versions | MediatR pinned to 12.5; AutoMapper takes an optional licence key |
| Validation errors (400) came back without the `errors` field | Testing the API by hand | Fixed in the global middleware |
| Request logs showed 500 for validation errors | Reading the Docker logs | Moved request logging outside the error middleware |
| Hire dates showed one day early in the UI | Clicking through the app | Removed a wrong time-zone argument |
| Google rejected sign-in (`origin_mismatch`) | Trying Google sign-in | Register `http://localhost:8080` and `http://localhost:4200` as authorised origins in Google Cloud Console |
| Secrets in the repository | Checked before every push | Keys and passwords only in `.env` / user-secrets; `.env.example` committed |

**Verification:** 78 backend unit tests (xUnit) and 33 front-end tests (Vitest) pass; every endpoint was called by
hand (success and 400/401/403/404/409/422 cases); every screen was clicked through, with `ng serve` and in Docker.
